# 文档指令

## 职责与层级

- `REQUIREMENTS.md` 是需求合同：定义范围、优先级和产品/架构决策。
- `SPEC.md` 是可执行技术规范：定义 API、文件格式、状态机、错误码和数值门禁；与实现冲突时以此为准。
- `plans/` 保存里程碑计划、执行记录与评审材料，描述当时范围，不应悄悄改写已完成工作的历史事实。

## 编辑规则

- 修改需求或 SPEC 时，明确记录版本、变更缘由、影响范围和需要同步的测试/实现；禁止只改代码或只改文档之一造成漂移。
- 保持对具体章节的引用稳定。重排大段内容前，先检查代码注释、CI 和计划文档中的交叉引用。
- 不将构建产物、测试日志或一次性分析输出混入长期规范。

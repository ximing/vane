# 10-ci-m1：M1 CI 门禁扩展

> SPEC 引用：§13.2（质量门禁）、§13.3（工程纪律）、§12.2（目标矩阵）、§13.1（性能）。
> 前置依赖：全部 M1 功能计划（01-09, 11, 12）。

## Goal

扩展 CI 门禁覆盖 M1 全部质量锚点：recall 真实回归 job、wasm 体积门禁（≤800KB gzip）、词典体积门禁（≤1.5MB / <2MB）、Go 交叉编译矩阵、冷启动 bench。所有门禁硬卡（fail 即阻断 merge）。

## Architecture

- **`ci.yml` 扩展**：
  - `wasm32-size` job：`cargo build --release --target wasm32-unknown-unknown -p vane-core` → `wasm-opt -Oz` → gzip size check ≤800KB。
  - `dict-size` job：`@vane/dict-zh` ≤1.5MB gzip + Go embed <2MB + 三渠道哈希一致。
  - `go-cross` matrix job：zig cc 交叉编译 `libvane-{triple}.a`（6 平台）。
  - `cold-start` job：调 11 计划 bench，断言 <1s 或分级降级。
  - `jieba-compat` job：200 句与 jieba-rs 原版 100% 一致。
- **`recall.yml`（新）**：`cargo test --test recall_regression -p vane-core`（五档选择率，12 计划）。
- **`release.yml` 扩展**：Go staticlib matrix build + publish。

## TDD 任务清单

### Task 1：wasm32 体积门禁 job

**测试**（`scripts/check-wasm-size.sh`）：
```bash
#!/usr/bin/env bash
set -euo pipefail
cargo build --release --target wasm32-unknown-unknown -p vane-core --no-default-features 2>/dev/null || \
  cargo build --release --target wasm32-unknown-unknown -p vane-core
WASM=target/wasm32-unknown-unknown/release/vane_core.wasm
# wasm-opt 若不可用则跳过优化（CI 装 binaryen）
if command -v wasm-opt &>/dev/null; then
  wasm-opt -Oz "$WASM" -o "${WASM}.opt"
  WASM="${WASM}.opt"
fi
SIZE=$(gzip -c "$WASM" | wc -c)
MAX=$((800 * 1024))
echo "wasm gzip size: $SIZE bytes (max $MAX)"
if [ "$SIZE" -gt "$MAX" ]; then
  echo "FAIL: wasm gzip > 800KB"; exit 1
fi
```
**ci.yml job**：
```yaml
wasm32-size:
  needs: test
  runs-on: ubuntu-latest
  steps:
    - uses: actions/checkout@v4
    - uses: dtolnay/rust-toolchain@stable
      with: { targets: wasm32-unknown-unknown }
    - name: Install binaryen
      run: sudo apt-get install -y binaryen
    - name: Check wasm32 gzip size ≤800KB
      run: bash scripts/check-wasm-size.sh
```
验证：本地 `bash scripts/check-wasm-size.sh` 通过（M0 无 jieba 应远 <800KB）。
commit：`ci: add wasm32 size gate (≤800KB gzip)`。

### Task 3：词典体积门禁 job

**scripts/check-dict-size.sh**：
```bash
#!/usr/bin/env bash
set -euo pipefail
# Node @vane/dict-zh
NODE_SIZE=$(gzip -c crates/vane-dict-zh/data/dict.bin | wc -c)
NODE_MAX=$((1500 * 1024))
echo "node dict gzip: $NODE_SIZE (max $NODE_MAX)"
[ "$NODE_SIZE" -le "$NODE_MAX" ] || { echo "FAIL: node dict >1.5MB"; exit 1; }
# Go embed
GO_SIZE=$(stat -c%s bindings/go/dict/dict.bin.gz 2>/dev/null || stat -f%z bindings/go/dict/dict.bin.gz)
GO_MAX=$((2 * 1024 * 1024))
echo "go embed: $GO_SIZE (max $GO_MAX)"
[ "$GO_SIZE" -le "$GO_MAX" ] || { echo "FAIL: go embed >2MB"; exit 1; }
```
**ci.yml job**：
```yaml
dict-size:
  needs: test
  runs-on: ubuntu-latest
  steps:
    - uses: actions/checkout@v4
    - name: Check dict size gates
      run: bash scripts/check-dict-size.sh
```
commit：`ci: add dict size gates (node ≤1.5MB, go <2MB)`。

### Task 5：Go 交叉编译矩阵 job

**release.yml / ci.yml job**：
```yaml
go-cross:
  needs: test
  strategy:
    fail-fast: false
    matrix:
      include:
        - { target: x86_64-unknown-linux-gnu, cc: zig, os: ubuntu-latest }
        - { target: aarch64-unknown-linux-gnu, cc: zig, os: ubuntu-latest }
        - { target: x86_64-unknown-linux-musl, cc: zig, os: ubuntu-latest }
        - { target: aarch64-apple-darwin, cc: zig, os: macos-14 }
        - { target: x86_64-apple-darwin, cc: zig, os: macos-13 }
        - { target: x86_64-pc-windows-msvc, cc: cl, os: windows-latest }
  steps:
    - uses: actions/checkout@v4
    - uses: dtolnay/rust-toolchain@stable
      with: { targets: ${{ matrix.target }} }
    - name: Install zig
      run: pip3 install ziglang  # 非 windows
    - name: Build staticlib
      run: |
        export CC_${{ matrix.target }}="zig cc -target ${{ matrix.target }}"
        cargo build --release -p vane-ffi --target ${{ matrix.target }}
    - name: Verify .a produced
      run: ls -la target/${{ matrix.target }}/release/libvane_ffi.a
```
commit：`ci: add Go cgo staticlib cross-compile matrix`。

### Task 7：nDCG 维基 fixture 生成 + CI job（§13.2-2 ②，Q-8）

**fixture 生成脚本**（`scripts/ndcg-fixture/gen.sh` + `scripts/ndcg-fixture/gen.py`）：
- **来源**：离线抓取中文维基百科 500 篇条目（用 `wikimedia` REST API 或 wikiextractor 处理 dump），+ 50 个查询（手工 + 从条目标题采样）。
- **基线标注**：对每个查询，用 jieba-rs 原版（完整词典）切分 → BM25 检索 → 取前 10 结果作为 relevance 基线（替代人工标注，降级为「jieba-rs 基线 nDCG」）。relevance 分档：基线 top10 命中 = 1，否则 = 0（二值 relevance，简化）。
- **fixture 产物**（提交仓库，避免 CI 抓取维基）：
  - `tests/fixtures/ndcg_wiki_500.jsonl`（500 篇文档：id + text）
  - `tests/fixtures/ndcg_queries_50.json`（50 查询 + 每查询基线 top10 id 列表）
- **CI job**：
```yaml
ndcg-wiki:
  needs: test
  runs-on: ubuntu-latest
  steps:
    - uses: actions/checkout@v4
    - uses: dtolnay/rust-toolchain@stable
    - name: Run nDCG regression (jieba-lite vs jieba-rs baseline vs bigram)
      run: cargo test --test ndcg_wiki -p vane-core --features jieba --release
```
- **断言**（`tests/ndcg_wiki.rs`）：
  - jieba-lite 相对 jieba-rs 完整版 nDCG@10 差 <2%（SPEC §13.2-2 ②）。
  - jieba-lite 相对 cjk_bigram nDCG@10 提升 ≥15%（SPEC §13.2-2 ②）。
- **降级方案**（文档化）：若维基语料获取困难（网络/dump 体积），改用合成中文语料 500 篇（确定性生成 + 注入 jieba 词典词）+ 50 查询，标注「合成语料降级」并在 CI job 名标注。合成语料仍跑 nDCG 断言，但门禁降为「报告值不阻断 merge」（标注降级），等维基 fixture 就绪后恢复硬门禁。
commit：`ci: add nDCG wiki fixture generation + regression job (Q-8, §13.2-2 ②)`。
